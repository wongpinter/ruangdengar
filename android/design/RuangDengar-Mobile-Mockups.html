Design → Compose

Satu sistem, semua layar.

Pola atomik mengatur tanggung jawab komponen, bukan membuat komponen baru untuk setiap elemen kecil. Token semantik menjadi sumber tunggal; layar menggunakan komponen yang sama untuk buku, status, formulir, navigasi, dan pemutar.

Kontrak state dan implementasi

Setiap halaman data: loading → content / empty / error. Refresh mempertahankan konten. Mutation: idle → pending → success / error; retry mempertahankan draft. Download: queued → downloading → paused / failed → available. Pemutar: preparing → playing / paused → buffering / recoverable error. Tombol tidak menjanjikan fitur yang belum tersedia.

Pemeriksaan yang dijalankan

58 fungsi layar berhasil menghasilkan markup; semua ID layar unik dan seluruh destination navigasi ditemukan. Eksekusi JavaScript dan alur Beranda → Pemutar → Editor → Import → Save diuji dengan DOM stub, bukan browser. 113 tombol ikon memiliki label; seluruh target label checkbox ditemukan. Kontras pasangan token teks utama, sekunder, dan tombol yang diperiksa: 5.28–14.10:1. Pemeriksaan ini tidak menggantikan render, TalkBack, atau pengujian kontras semua state.

Handoff dan batas verifikasi

Ini mockup HTML yang dapat dibuka tanpa dependensi eksternal, bukan aplikasi Kotlin yang sudah dibuat. Semua interaksi adalah simulasi lokal. Layout memakai komponen/fungsi bersama dan token yang sama; layar pembanding menunjukkan kasus kosong, loading, offline, gagal, dan konflik. Pengujian render di emulator Android, TalkBack, font scaling 200%, keyboard, system insets, kontras seluruh state, dan playback perangkat nyata masih diperlukan sebelum persetujuan implementasi.
